# قِوام — FitCore

تطبيق وموقع لتتبّع الدايت والتمارين: أنظمة غذائية عالمية، تسجيل الوجبات
بالباركود والبحث واليدوي، تسجيل التمارين ومتابعة التطوّر، حساب السعرات
والماكروز تلقائياً، عدّاد خطوات من حسّاس الجوال، قراءة تقارير InBody،
ووحدة كاملة للمدرّب.

## بنية المستودع

| المجلد | وش فيه |
|---|---|
| `server/` | الـAPI بـASP.NET Core 8 — أربع طبقات، فايربيز للبيانات والهوية |
| `client/` | تطبيق React + TypeScript + Vite |
| `web/` | النموذج الأولي (ملف واحد يشتغل بفتحه بالمتصفح) |
| `design/` | لوحة التصميم — كل الشاشات كـ`.dc.html` |
| `native/` | غلاف Capacitor — الخطوات من صحة آبل وHealth Connect |
| `scripts/` | إعداد فايربيز والنشر |
| `docs/` | وثيقة المشروع وبرومبتات Stitch |

## التشغيل

```bash
cp .env.example .env            # املأ مفاتيح فايربيز ومفتاح Anthropic
mkdir -p secrets                # وحط service-account.json جواه
docker compose up --build       # الويب على :8080 والـAPI على :5126
```

أو محلياً بدون Docker:

```bash
dotnet run --project server/src/FitCore.Api     # http://localhost:5126/swagger
cd client && npm install && npm run dev          # http://localhost:5173
```

بدون `VITE_API_BASE` يشتغل الفرونت **بوضع تجربة**: كل شي في متصفحك،
تقدر تجرّب التطبيق كامل قبل ما تنشر السيرفر.

## التحقق

```bash
cd server && dotnet test                        # الحسابات + اختبارات تكامل على الـAPI كامل
cd client && npm run lint && npm run build      # فحص الأنواع والبناء
cd client && npm run smoke                      # مرور آلي على التطبيق المبني
```

CI في `.github/workflows/ci.yml` يشغّل الثلاثة ويبني صور Docker.

## التذكيرات

تحتاج Cloud Scheduler ينادي `/api/jobs/reminders` كل ربع ساعة بمفتاح `Jobs:Secret`
(الأمر في `server/README.md`). التذكير ما ينرسل إلا إذا الشي فعلاً ناقص.

## النشر

```bash
scripts/setup-firebase.sh <project-id>   # يفعّل الخدمات، ينشئ service account، ينشر القواعد والفهارس
scripts/deploy.sh <project-id>           # الـAPI على Cloud Run والويب على Firebase Hosting
```

الاستضافة تحوّل `/api/**` لـCloud Run، فالمتصفح يشوف origin واحد و`VITE_API_BASE=/`.
باقي خطوتين من الكونسول (ما تنكتب بسكربت): تفعيل Email/Password، وإنشاء bucket التخزين.

## الجوال

`native/` غلاف Capacitor يحقن `window.FitCoreNative` ليعطي الخطوات من صحة آبل أو
Health Connect. الويب يستخدمه لو موجود، وإلا يرجع لحسّاس الحركة — بدون ادعاء.

## قواعد فايربيز

`firestore.rules` و`storage.rules` مقفلة بالكامل عن المتصفح: الوصول كله يمر
بالـAPI اللي يتحقق من هوية صاحب الطلب. انشرها بـ:

```bash
firebase deploy --only firestore:rules,storage:rules
```

# النموذج الأولي والتصميم (المرحلة السابقة)


## نسخة الويب الشغّالة

`web/qiwam-app.html` — ملف واحد بدون أي مكتبات خارجية، يشتغل بفتحه في المتصفح.
يبدأ بحساب فاضي: ترحيب ← تسجيل دخول أو إنشاء حساب ← ٥ خطوات تهيئة
(الهدف، بياناتك، نشاطك، نظامك، خطتك) ← يومك يبدأ من الصفر.
شغّال فعلياً: تسجيل الوجبات (بحث · محاكاة باركود · يدوي · تكرار أمس)، حساب
السعرات والماكروز بمعادلة Mifflin-St Jeor، تبديل النظام الغذائي، تسجيل
مجموعات التمرين ومقارنة الحمل بالأسابيع السابقة، تسجيل الوزن وقراءة الميزان،
عدّاد الخطوات، ووضع المدرّب بكامل شاشاته. البيانات تُحفظ في `localStorage`
داخل متصفحك.

```bash
python3 -m http.server 8000   # ثم افتح http://localhost:8000/web/qiwam-app.html
```

## التصميم (مرجع الواجهات)

كل الشاشات في `design/` كملفات `.dc.html`، وتُعرض مجتمعة على لوحة تصميم
واحدة (Artifact) قابلة للتكبير والتنقل والتصدير PNG/PDF.

| المجموعة | الشاشات |
|---|---|
| التطبيق (داكن) | الرئيسية، اليوميات، إضافة طعام، ماسح الباركود، تفاصيل الصنف، أنظمة الدايت، تفاصيل النظام، التمارين، تسجيل تمرين، التقدّم، الميزان الذكي، المشي، حسابي |
| البداية وحساب الخطة | الترحيب، البيانات الجسدية، نتيجة الحساب |
| الوضع الفاتح | الرئيسية، اليوميات، الميزان |
| English (LTR) | Home، Add food |
| لوحة المدرّب | لوحة المدرّب، المتدربون، ملف المتدرب، وجباته مقابل الخطة، بناء خطة أكل، المراجعة الأسبوعية، المحادثة، إضافة متدرب، شاشة المتدرب |
| نظام التصميم | الألوان والخطوط والعناصر والأيقونات |

### أساسيات التصميم

- مقاس الشاشة: `390 × 844` — شريط علوي آمن `52px`، تبويب سفلي `88px`،
  هوامش جانبية `20px`، وأصغر هدف لمس `44 × 44`.
- الخطوط: `Readex Pro` للنصوص العربية والإنجليزية، و`Space Grotesk` للأرقام.
- اللون الأساسي `#C8F751`، والماكروز: بروتين `#C8F751`، كارب `#7FD4FF`،
  دهون `#FFC46B`.

## دليل البناء وبرومتات Stitch

`docs/qiwam-build-guide.html` — صفحة واحدة فيها فكرة المشروع كاملة (المشكلة،
المستخدمون، خريطة الشاشات ٣٤ شاشة، الكيانات والمعادلات، التكاملات، نظام
التصميم، خطة الإصدارات، مصادر الربح) و**٣٥ برومت جاهز للنسخ** لتوليد الشاشات
في Google Stitch: برومت ستايل واحد يثبّت الألوان والخطوط واتجاه RTL، ثم برومت
مستقل لكل شاشة بنصوصها العربية الفعلية.

## بنية الملفات وإعادة البناء

```
design/
  parts/head-dark.html    # كل أصناف CSS للوضع الداكن
  parts/head-light.html   # نفس الأصناف بقيم الوضع الفاتح
  parts/nav.html          # شريط التبويب السفلي (المتدرب)
  parts/nav-coach.html    # شريط التبويب السفلي (المدرّب)
  parts/body-<screen>.html# محتوى كل شاشة (بدون ألوان ثابتة للنص)
  build.py                # يركّب: head + body + nav → <Name>.dc.html
  canvas.json             # ترتيب اللوحة وصفحاتها
```

الشاشة الواحدة تشتغل بالوضعين لأن ألوان النصوص والأسطح تجي من أصناف
(`t1`, `t2`, `card`, `accent` …) معرّفة في الـ head، مو مكتوبة داخل العنصر.

```bash
python3 design/build.py   # إعادة توليد كل ملفات .dc.html
```
