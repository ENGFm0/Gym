# الوثائق النظامية

النص مصدره واحد: `client/src/lib/legal.ts`. التطبيق يعرضه في `/legal/privacy`
و`/legal/terms`، والملفات هنا نسخة markdown لصفحات المتجر أو موقع خارجي.

```bash
cd client && node scripts/legal-docs.mjs   # يعيد توليد الملفات الأربعة
```

## قبل النشر — ثلاث خانات لازم تُملأ

عدّلها في `client/src/lib/legal.ts` ثم أعد التوليد:

| الثابت | الحالي | وش يصير |
|---|---|---|
| `OPERATOR` | `[اسم الجهة المشغّلة]` | اسم الشركة أو المؤسسة اللي تشغّل التطبيق كما هو في السجل التجاري |
| `CONTACT` | `[البريد للتواصل]` | بريد يستقبل طلبات الخصوصية فعلياً (تنزيل، حذف، اعتراض) |
| `JURISDICTION_AR` / `JURISDICTION_EN` | `[المملكة العربية السعودية]` / `[Saudi Arabia]` | الدولة اللي تخضع لأنظمتها |

كذلك `UPDATED` في نفس الملف — حدّثه مع أي تعديل جوهري.

## وش يغيّر النص إذا تغيّر الكود

النص مكتوب على اللي يسويه المشروع فعلاً، فأي من هذي التغييرات يستوجب تعديله:

- إضافة أي طرف ثالث جديد يستقبل بيانات (اليوم: قوقل/فايربيز، Anthropic لقراءة
  InBody، وOpen Food Facts للباركود إذا فعّلها المشغّل).
- تغيير مدة الحفظ أو الاحتفاظ بصور InBody بعد قراءتها.
- أي مشاركة للبيانات لأغراض تحليلية أو تسويقية — اليوم ما فيه ولا واحدة.
- توسيع ما يشوفه المدرّب، أو تغيير لحظة بداية وصوله (اليوم: بعد القبول فقط).

> هذي صياغة مبنية على وظائف التطبيق، ومو بديلاً عن مراجعة قانونية قبل النشر
> في متجر أو في سوق فيه متطلبات خاصة.
